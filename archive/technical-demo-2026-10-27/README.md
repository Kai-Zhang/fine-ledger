# Fine Ledger · PWA 交互 Demo

基于 [首版需求](docs/requirements.md) 的可运行原型。优先验证本机优先 PWA、主要业务流程和状态区分，使用合成数据，不连接银行、不读取真实 MoneyWiz 备份。

## 运行

需要 **Node.js 24 或以上**（使用内置 `node:sqlite`），无第三方运行依赖，无需安装依赖和构建。

```sh
npm start
```

打开 <http://127.0.0.1:4173>。浏览器首次联网初始化后准备离线资源。请使用普通浏览模式，不要用隐私模式测试持久化。

```sh
npm run check
npm test
```

测试包含独立临时 SQLite / HTTP 服务，不修改 `data/nas.sqlite`。测试需要允许监听本机临时端口。

## 已覆盖的交互

| 入口 | 可以验证的内容 |
| --- | --- |
| 记一笔 | 支出、收入、转账、关联退款、余额调整；原币与账户金额、最近描述、草稿恢复、连续记账、撤销 |
| 分类与项目 | 多级分类、精确拆分、逐项旅游项目、账户及分类和项目归档、更名与排序 |
| 银行入账 | 信用卡待入账、原币和 USD 中间金额、同一记录确认正式金额、撤销未入账消费 |
| 信用卡还款 | 同币种 / 跨币种转账、两端实际金额、关联独立手续费、保存后稍后分配成本 |
| 成本来源 | CNY → 外币信用卡、先购汇到外币账户再还款、手动选择消费覆盖量、部分 / 多次结算、来源余款与整数尾差 |
| 退款 | 多个原拆分项、部分 / 多次退款、不同到账账户和币种、原分类及项目继承、可退量、已结算历史成本冲减和汇兑差额 |
| 账单 | 描述 / 备注搜索，日期、账户、类型、分类、项目、入账、对账与成本状态组合筛选；编辑、逻辑删除、恢复与修订历史 |
| 报表 | 月 / 季收支、分类树下钻、项目分类构成及明细、原币余额和余额历史、净资产参考估值、未定价缺口、待处理 |
| 对账 | 外部期末余额、起始余额和期间变动、逐项勾选、草稿、完成前同步及其他设备确认、余额变动显式重新打开后续批次 |
| 同步 | 启动 / 前台恢复 / 保存 / 前台 30 秒重试；事务队列、操作 ID 幂等、版本检查、冲突选择双方版本、游标增量拉取 |
| 数据与 PWA | 完整 JSON 导出与恢复预览、合成迁移预览、持久化存储申请、安装指引、本机保存耗时观测、离线演练 |

「已保存到本机」「已同步到 NAS」「已入账」「已对账」「成本确定」分开表达。CNY 信用卡消费入账即可确定成本，不等待还款。转账和调整不计日常收支，退款单独展示。待入账不计正式账户余额。

## 推荐演示路线

1. **本机记账**：新增一笔支出，选择拆分和旅游项目，保存；在设置开启离线演练，再记一笔，关闭重开查看队列及记录。未保存输入也会恢复。
2. **真实断网**：先确认设置页「离线资源就绪」，停止服务，关闭页面后重开同一地址。保存交易、查询及报表应可使用。恢复服务后保持前台，30 秒内自动重试同步。
3. **银行折为 CNY**：账单找到「京都酒店」，原币 10,000 JPY、中间 67 USD、暂估 ¥482.40。确认实际 CNY 入账 ¥490；原交易 ID、消费日期及历史金额保留，CNY 信用卡正式余额减少 ¥490。
4. **直接购汇还款**：成本来源 → 记跨币种还款，转出 720 CNY，转入美元信用卡 100 USD。选择 40 / 60 USD 两笔消费，预览并确认 ¥288 / ¥432；还款没有第二次增加支出。
5. **先换汇再还款**：先记 720 CNY → 美元储蓄 100 USD。再记美元储蓄 → 美元信用卡，选择上游成本来源。成本传递时扣减来源可用额度，不重复创造成本。
6. **部分退款**：原支出详情 → 关联退款，填写对应原币量与实际到账量。每个拆分继承分类与项目。超过可退额会拒绝保存。
7. **对账**：设置 → 账户对账，填入当前账户正式余额并勾选明细，核实其他设备后完成；待入账不参与。再修改已完成期间的金额，要求显式重开批次。
8. **多设备冲突**：使用两个不同浏览器或独立浏览器配置文件连接同一服务。先都初始化，均开启离线演练，编辑同一笔记录为不同金额；依次恢复同步，在设置中检查双方版本并选择。普通的同浏览器两个标签页共用 IndexedDB，不能当成两个设备。
9. **备份恢复**：导出 JSON，预览账户原币余额，再在队列清空且无冲突时恢复。JSON 仅补入缺失记录，保留较新数据；有差异会拒绝覆盖。完整灾难恢复见 P0 的快照加日志工具。

合成初始数据固定 ID，可重复验证。当前演示实例可能保留浏览器验证时新增的合成记录。要隔离一轮验证，可使用不同的数据库路径和浏览器配置文件；不要为了重置而清理真实账本。

## iPhone / 家庭 NAS 验证

同一家庭 Wi-Fi 的可运行 HTTPS 测试工具已提供：`npm run iphone:setup`、`npm run iphone:start`。使用测试 CA、独立账本和口令，详细安装、离线冷启动及服务端回执核验步骤见 [iPhone 真机验证](docs/iphone-validation.md)。

电脑的 `http://127.0.0.1` 可作为本地安全上下文；iPhone 访问普通局域网 HTTP IP 不具备完整 Service Worker 能力。真机验证应由 NAS 使用稳定域名及受信任 HTTPS 证书，通过同一来源代理页面和 `/api/*`。

服务默认只监听 `127.0.0.1`。部署到 NAS 时可通过环境变量调整：

```sh
HOST=0.0.0.0 PORT=4173 LEDGER_DB=/volume1/fine-ledger/nas.sqlite LEDGER_TOKEN='<自己的连接口令>' npm start
```

在客户端首次初始化页 / 设置中填写同一口令。此口令认证只是原型保护，不是完整生产会话管理。请只在可信家庭网络测试，并由 HTTPS 反向代理对外提供稳定同源地址。不要直接把未认证端口暴露到互联网。

iOS：Safari → 分享 → 添加到主屏幕。先在家联网初始化并等待「离线资源就绪」，再测试飞行模式、强退与冷启动；最后回到家庭网络检查队列归零。域名、端口或协议改变会成为新的浏览器存储来源。

## 实现结构

- `public/domain.js`：两端共享的业务约束，金额为最小单位整数字符串，计算使用 BigInt；CNY 分值用确定性分配。
- `public/storage.js`：IndexedDB 单事务提交业务聚合、修订历史与待同步操作；网络请求在事务之外。
- `public/app.js` / `style.css`：无需构建的响应式界面，手机四个主入口、桌面键盘录入、弹层详情与对账。
- `public/sw.js` / `manifest.webmanifest`：离线应用壳与安装资源，不缓存 API，不承诺后台执行。
- `server.mjs`：同源静态服务、SQLite WAL、操作幂等、聚合版本校验、历史快照、增量游标与显式冲突。
- `lib/recovery.mjs` / `scripts/recovery.mjs`：独立日志目录、快照、启动重放与全量灾难恢复。
- `public/reliability*`：仅独立测试环境可用的 IndexedDB 故障与清空恢复实验室。
- `test/`：精确金额、关键业务规则和 SQLite / HTTP 同步测试。

服务端数据在 `data/nas.sqlite`，浏览器数据在本来源的 IndexedDB。二者都是实际持久化，不是延时模拟同步。正式备份时请使用 SQLite 在线备份机制，或停止服务后一起备份数据库、WAL / SHM 文件，保存到另一故障介质。实时同步不等于独立备份。

## 当前限制

- **不代表正式首版全部验收完成**。本轮已在用户 iPhone 上验证受信任 HTTPS、主屏幕独立运行、服务停机时冷启动和保存、划掉重开后保留、恢复服务自动补传且不重复。真实 NAS 部署、其他机型、多设备长期离线、存储淘汰及性能目标仍待验收。证据见 [真机验证记录](docs/iphone-validation.md)。
- MoneyWiz SQLite / WAL 转换尚未实现。入口只处理明确标记的合成 JSON 中间格式；预算与旧标签演示归档保留，可随备份导出。没有用真实备份测试。
- 还款覆盖顺序不设默认，由用户填写并确认。已确认分配只追加，不静默重排；撤销和重分摊已有成本链、已退款本金的复杂更正需要后续专门流程。
- 退款关联已结算成本可追溯，但退款产生的外币预存资金尚未自动建立可复用成本来源。外币期初资产成本批次录入、外币非信用账户消费的来源选择也未完整开放。
- 先购汇再还款支持同一外币的来源传递；复杂跨多个不同外币的资金链尚不支持。
- JSON 备份只补入缺失记录，不覆盖已有差异或删除较新记录。服务端已提供完整快照加增量日志恢复，保留原操作 ID 及回执。浏览器修订历史保留最近 500 次；跨机器自动备份、日志安全裁剪及长期设备换代策略仍未实现。
- 单设备同步串行、服务端 SQLite 事务串行。当前服务保留全部增量，响应附完整状态供冲突审阅；未针对 16,000+ 笔真实迁移账本做索引与体积优化。
- 自动化测试和当前浏览器观测不代表 iPhone 保存 P95 ≤200ms 或离线冷启动 ≤2 秒已经达成。

详见 [验证记录](docs/demo-validation.md)。

## P0 可靠性验证

使用独立合成账本，覆盖本机清空重建、保存及同步中断、旧快照加完整日志恢复。见 [使用说明](docs/reliability-p0.md) 与 [本轮测试报告](docs/reliability-p0-report.md)。iPhone 实验室使用 `npm run reliability:iphone:start`，端口 8444，与原 8443 账本分开。

新版服务会建立 `${LEDGER_DB}.recovery`（可用 `LEDGER_RECOVERY_DIR` 指定）并在成功回执前 fsync 增量日志。恢复目录必须一起保护，缺失或损坏时拒绝静默继续。该目录仍在同一台机器上，不能代替跨机器独立备份。

# iPhone HTTPS 与真机验证

本轮使用同一家庭 Wi-Fi 中的 Mac 临时承载 HTTPS 与同步服务。当前仍是合成数据 demo，不代表已迁移到真实 NAS。创建独立的 `.local/iphone/iphone-demo.sqlite`，不更改原 `data/nas.sqlite`。

## 启动和地址

需要 Node.js 24+、OpenSSL。无需安装第三方包，也不修改 Mac 钥匙串。

```sh
npm run iphone:setup
npm run iphone:start
```

`setup` 自动选择实际家庭网 IPv4 地址和 Mac 的 Bonjour `.local` 名称，签发测试根证书和 30 天服务器证书。重复执行沿用根证书与连接口令；IP 改变可重新签发服务器证书。`.local/` 不纳入版本控制，目录权限 700，私钥与连接信息权限 600。

主访问地址、IP 备用地址、证书下载地址、根证书指纹和初始化口令保存在 `.local/iphone/connection.txt`。主地址使用 Bonjour 主机名，避免 DHCP 地址变化导致 PWA 存储来源变化。测试应选定一种地址后始终沿用，不能在同一次离线验证中切换域名与 IP。

仅当前家庭网 IPv4 接口监听 HTTPS 8443 和证书下载 HTTP 8180。API 后端仅监听 loopback 4174 并要求独立测试口令。HTTP 端口只提供证书说明页及公开 CA 证书，不提供 API、口令或私钥。反向代理保留来源 Host / Origin，API 仍校验同源。

```sh
npm run iphone:status
npm run iphone:stop
```

`status` 使用项目 CA 严格校验证书，不跳过 TLS 校验，返回已连接设备、客户端报告以及在服务器账本中确认存在的样例 ID 和金额。`stop` 保留数据库和证书。

可通过 `IPHONE_LAN_IP`、`IPHONE_HTTPS_PORT`、`IPHONE_SETUP_PORT`、`IPHONE_BACKEND_PORT` 调整网络参数；只接受本机实际存在的局域网接口。改 HTTPS 端口也是改变存储来源，测试中不要随意调整。

## 第一步：由用户在 iPhone 上信任证书

1. iPhone 与 Mac 接入同一家庭网络，用 **Safari** 打开配置页，下载 `fine-ledger-demo-ca.cer`。
2. 对照 Mac 连接信息中的根证书名称与完整 SHA-256 指纹。
3. 在设置中安装已下载的证书描述文件，再打开「通用 → 关于本机 → 证书信任设置」，开启这张证书的完全信任。安装证书不会自动开启 SSL 信任。[Apple 说明](https://support.apple.com/zh-cn/102390)
4. 打开连接信息中的 HTTPS 主地址，首次初始化填写同一文件中的口令。应正常进入应用，无证书警告。

根证书完全信任会扩大 iPhone 接受的证书范围。必须由用户亲自核对并操作；不要绕过 Safari 的证书警告。如果仍有警告，先核对证书、访问主机名与日期。

测试结束后在「设置 → 通用 → VPN 与设备管理」移除这张测试 CA 描述文件。不要把根私钥、服务器私钥、连接口令上传到其他服务。HTTP 配置页传输的是公开证书，应通过独立的 Mac 本地连接文件核对指纹。

## 第二步：添加到主屏幕并再次联网准备

1. Safari 打开应用 → 设置，确认「安全上下文：满足」「离线资源就绪」，操作队列为零。
2. Safari 分享 → 添加到主屏幕；如果出现「作为网页 App 打开」，保持开启。[Apple 操作说明](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)
3. **从主屏幕图标联网打开一次**。Safari 标签页与独立网页应用的存储环境不能假定已完全共享，须在这个窗口重新核实初始化、口令和离线资源。
4. 设置 →「iPhone 完整流程验证」，看到「已观测到独立应用」「完整且已接管页面」，并确保离线演练开关关闭。
5. 点「准备联网样例 ¥12.34」，检查表单并保存。回到验证面板检查服务器回执与队列归零。

## 第三步：真实离线冷启动与保存

1. 开启飞行模式，**另行确认 Wi-Fi 已关闭**。iOS 飞行模式可能保留 Wi-Fi，不能仅凭飞机图标判断断网。
2. 从应用切换器划掉应用，再从主屏幕图标重开。不要仅切换到后台再回来。
3. 应可以进入记账页、查看账单和报表。等同步请求失败显示本机模式；验证面板应记录独立启动时 API 不可达。
4. 点「准备离线样例 ¥56.78」，保存后等待明确的「已保存到本机」反馈，队列增加。
5. 再次划掉应用、从主屏幕重开，确认该笔记录、金额及待同步数量仍在。此时不要清除 Safari 数据、删除主屏幕 App 或切换访问来源。

## 第四步：恢复联网并核对服务器

1. 关闭飞行模式并重新连接家庭 Wi-Fi，把应用恢复前台；不按同步按钮，观察是否自动尝试同步。前台也会每 30 秒重试。
2. 验证面板应显示两笔样例均收到服务器回执，队列归零，无冲突。
3. Mac 执行 `npm run iphone:status`。核对对应设备的两笔 `serverConfirmed`，金额分别为 `1234` 与 `5678`（CNY 分），对应描述含同一轮验证 ID。
4. 最后关闭并重开主屏幕应用，确认两笔各一条、原币余额及报表合理，没有因恢复同步产生重复交易。

验证面板在本机保存启动与样例提交观测，随已有同步通道发送到这台 Mac；不记录口令。服务端区分客户端自报信息与账本中实际存在的样例，不凭队列归零宣称已验证系统飞行模式。

## 访问失败时

- HTTP 配置页打不开：检查 iPhone 与 Mac 是否在同一非访客网络，是否启用无线客户端隔离，以及 macOS 是否弹出 Node 的传入连接请求。不要为测试整体关闭防火墙。
- `.local` 名称无法解析：可从一开始选用 IP 备用地址；若已在主地址保存未同步记录，先恢复原地址完成同步，再安排来源切换。
- HTTPS 有证书警告：核对已安装且完全信任的测试 CA 名称、叶证书 SAN 中的主机名以及设备日期。
- 页面可打开但无法初始化：口令错误与本机数据问题分开检查。已有本机账本遇到认证过期仍应能记账。
- 离线出现浏览器错误页：返回联网状态，在**主屏幕应用本身**重新准备资源并检查控制器；此前不能宣称离线冷启动通过。

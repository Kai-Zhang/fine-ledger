# 厘序视觉设计方案比较

日期：2026-10-30
状态：纸白松绿已由用户选定，0.8.0 实施；其他两套保留为比较稿

建议采用“纸白松绿”，把松绿用于操作与选中状态，纸白用于数据阅读，暖金只作为品牌识别。它延续账簿与硬币图标，又能减少当前页面的泛绿感。另提供“雾白靛蓝”和“暖纸墨灰”，比较视觉气质、列表组织和数字排版。

本轮选择一套作为统一基线，产品保留跟随系统、浅色和深色三种外观。账户、记账、交易和报表沿用已确定的功能与导航。备份导入按原阶段推进。纸白松绿已在 0.8.0 落地，见 [实施与验证记录](../docs/frontend-review-v0.8.0.md)。

## 三套方向

| 项目 | [纸白松绿](evidence/visual-directions/pine-accounts-light.png) 推荐 | [雾白靛蓝](evidence/visual-directions/indigo-accounts-light.png) | [暖纸墨灰](evidence/visual-directions/ink-accounts-light.png) |
| --- | --- | --- | --- |
| 气质 | 清楚、温和、适合长期个人记账 | 理性、利落、偏财务工具 | 安静、克制、接近实体账簿 |
| 页面组织 | 按账户分组共享白色面板，组内用细分隔线 | 平面列表，组头与行列对齐，减少容器 | 纸色底与细横线，组头像账簿章节 |
| 视觉重心 | 内容与主动作；大面积使用中性色 | 数字与列对齐；蓝色仅强调操作 | 名称与金额的阅读节奏；用墨色强调操作 |
| 字体差别 | 系统无衬线，数字启用等宽数字特性 | 系统无衬线，标题和金额稍强 | 中文系统无衬线，结构化金额用本地等宽字体 |
| 圆角 | 分组面板 12，输入 10，主按钮 12 | 面板与输入 8，主按钮 8 | 面板与输入 6，主按钮 6 |
| 图标 | 松绿底、纸白账簿、暖金硬币 | 深靛蓝底、冷白账簿、淡金硬币 | 深墨灰底、暖纸账簿、古铜硬币 |
| 主要代价 | 与当前最接近，需要靠规范化而非装饰体现提升 | 品牌气质更偏工具，亲和感稍弱 | 等宽金额更占横向空间，窄屏和多币长金额需要更多测试 |

推荐纸白松绿的理由是：已有图标和页面可以归入同一套语言；密集中文和数字仍有足够对比；类目颜色能与品牌绿分开；朋友使用时也保持通用工具的气质。选雾白靛蓝时，保留同样的信息密度，改变的是平面组织与更强的数字层级。

深色模式使用有层级的暗表面，避免整页纯黑和大面积饱和品牌色。品牌安装图标保持自身颜色，页面控件根据明暗调整。完整变量见 [配色数据](visual-theme-proposals.json)。

### 颜色语义

- 普通账户正余额使用正文色；负余额使用负向色并保留负号。信用卡欠款采用同一规则，不能只靠红色表达负数。
- 支出和收入保留负号/正号，退款标明“退款”；退款属于退回金额，不直接作为普通收入展示。普通同币转账使用中性色与方向图标，避免看成又一笔消费。
- 未入账使用虚线状态图形和文字，不用错误红；正式报表仍排除未入账。错误红留给无效输入、删除等明确语义。
- 当前筛选显示品牌轻底、文字或勾选；同时通过形状/文字标识。图标与类目配色不改变金额语义。

## 字体与数字

中文优先使用设备系统无衬线：iOS/macOS 为 PingFang SC 与系统拉丁字体，Windows 为 Segoe UI 加 Microsoft YaHei，Android 为系统 sans。不下载在线字体，字体与图标随离线能力一起工作。常规正文 400，强调 500，标题及金额可用 600；避免把整屏账户名都设成粗体。

| 层级 | 字号与行高 | 用途 |
| --- | --- | --- |
| 页面标题 | 24 / 32，600 | 账户、交易、报表、设置 |
| 总净值 | 32 / 40，600 | 首页单个汇总值；不再扩大成宣传页标题 |
| 录入总金额 | 36 / 44，500 | 保持主要输入位置，避免挤压描述和类目 |
| 账户名与交易描述 | 16 / 22，500 | 列表第一行 |
| 账户与交易金额 | 16 / 22，500–600 | 固定右对齐，按列对齐小数 |
| 正文与表单输入 | 16 / 24，400 | 可编辑输入维持 16，不通过小字压缩表单 |
| 分组、类目与筛选标签 | 13 / 18，400–500 | 清楚但次于交易名称 |
| 时间、币种、次要状态 | 12 / 16，400 | 仍应具有足够对比；不使用 9–10px 常用文字 |

金额启用 `tabular-nums`，中文名称仍按正常字宽。货币代码使用次要字号；账户余额保留本币，汇总以主币显示。不同币种遵守各自小数位规则，不统一强迫两位；JPY 金额不显示 .00。只在暖纸墨灰方案中，金额列另用 `ui-monospace` 本地字体，正文仍为系统无衬线。

数字与币种不要在窄屏互相挤压。账户名过长时允许截断并从详情读全；放大字体时优先让辅助信息换行、增加行高，不缩小金额或把核心单位隐藏。

## 布局和密度

以 4px 为间距基准，常用 4、8、12、16、24。手机主内容左右 16px，宽屏可增加到 20px。账户与交易优先使用整行信息，不为每一笔创建独立浮起的小卡片。

| 元素 | 建议尺寸 |
| --- | --- |
| 常规账户行 | 56–60px，名称/币种两行、金额右对齐 |
| 常规交易行 | 50–52px，描述/类目时间两行 |
| 单行分组标题 | 28–32px；分组间 12–16px |
| 可操作图标热区 | 至少 44×44px，图形本身 20–22px |
| 类目与账户图形 | 类目 20px，账户容器 32–36px；图形仍为 20px |
| 常规输入与主按钮 | 最小 48px |
| 浮动记账入口 | 52px，靠近右下；避开底栏与安全区 |
| 候选描述条 | 40–44px，单行横向滚动 |
| 底部导航 | 56px 加系统安全区，四个固定主入口 |

390×844 的常见账户流水目标为一屏约 9–11 笔，受状态栏、日期分组及字体大小影响。通过减少无用留白、重复标签和容器层级提高密度，不牺牲核心文字与点击区域。没有键盘时描述候选靠近输入框；键盘打开时使用已确定的网页候选条位置，不重画系统拼音选词栏。

## 图标与品牌

品牌保留“账簿＋硬币”大轮廓，只有安装、启动、建账和设置等品牌位置展示完整标识。三套方向只比较对应的颜色与明暗，不同时更换图形概念。

业务图标统一使用本地 Lucide，20px 图形以约 1.75px 线宽为基准，保持圆端点和相同视觉重量。选择方案后逐项校准，不混用 emoji、另一套实心图标或第三套银行插画。

- 管理为铅笔，记一笔为方框铅笔，筛选为漏斗，账户操作为省略号，归档为归档盒，排序手柄为拖动点；固定这些语义。
- 类目各自有明确图形：餐饮、咖啡、交通、购物等。颜色与图形同时区分，不能全部退化成标签符号。
- 品牌图形采用实心叠放，业务图标采用线性；二者通过配色、圆角和视觉重量归入同一套规范。数据区不重复装饰性硬币、账簿和金色。
- 图标无文字，安装素材保持不透明方形，由系统裁切；不要求用户删除主屏幕应用来更换图标。

## 组件与页面

账户页只保留标题、总净值、分组与原币余额、管理入口及记账入口。管理状态中用手柄、直接归档、浮动新增菜单表达操作，不额外增加说明文字。

记账页面将金额设为首要层级，账户、描述、类目组成连续信息区。拆分行按相同网格对齐图标、名称、金额、锁定与移除；总额及分配差额使用同一数字样式。时间为日期加连续时分秒，项目和备注默认折叠。主保存按钮与普通文本/图标操作分级。

交易列表保持双行紧凑，日期分组使用小型中性标题。点选、未入账和筛选分别使用轻底、虚线图形和筛选标签，避免多个强色同时争夺金额注意力。详情的金额层级可增加，普通列表不为展开细节预留大片空白。

报表目录保留可扩展的报表条目；进入单张报表后，范围、期间、总额、图形、金额明细按顺序排列。净值用单条品牌色曲线；支出分类用内圈一级、外圈二级的层级环图，父子使用同色系。图表旁的金额仍为正文色。

默认分类色在选定方向后固定，例如纸白松绿的餐饮 `#4E7D68`、购物 `#B7845D`、出行 `#5C7E9B`、休闲 `#8F78A5`。父子保持颜色家族；排序不改变颜色，切换深浅模式只调亮度，不交换类别身份，用户自选颜色继续保留。负净退款单列，饼图只展示正净支出，不用红绿饼图替代真实分类。

## 动效与反馈

普通页面或弹层转场约 180–260ms，轻量状态反馈约 120–180ms。滑动返回继续跟随手指和释放方向，完成时滑出、取消时回弹；根页只给阻尼。拖动保留跟手浮层、位置让位和正确落点，视觉方案不改变已确定的页面栈逻辑。

金额保存后立即显示结果，不用滚动数字、闪烁或载入动画掩盖实际值。加载仅在操作真正等待时出现，使用局部状态；离线保存不伪装成正在同步。减少动态模式下去掉非必要过渡。

## 可读性与验收

按 [WCAG 对比度规则](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，常规文字目标至少 4.5:1。当前三套浅/深模式的正文、次要文字、正负金额、提示文字和按钮文字共 78 组配色检查全部达到 4.5:1，最小 4.895:1，见[计算结果](evidence/visual-directions/contrast.json)。这是所列颜色对的检查，透明叠加、聚焦、禁用、截图及放大字体仍需在实现中分别核对。

系统字体及适配原则参考 [Apple 字体说明](https://developer.apple.com/documentation/technologyoverviews/fonts) 与 [Apple 界面可读性建议](https://developer.apple.com/design/tips/)。具体字号、间距和配色为厘序的设计提案。

选定方向后，以账户首页、10 条交易流水、含拆分的记账、交易详情、净值与分类报表、账户/类目管理、设置八类状态验证统一程度。检查浅/深色、320/390px、系统大字体、JPY 与长金额、键盘打开、焦点/禁用/错误，以及真实触屏滑动和拖动。先应用一套规范，再按真机结果细调。

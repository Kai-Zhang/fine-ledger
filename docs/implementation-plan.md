# 厘序分阶段实施计划

版本：0.21

日期：2026-11-03

当前实现基线：0.14.3；运行版本以 `package.json` 和实际发布标识为准。

当前目标是完成目标 iPhone 主屏幕 PWA 与常用桌面端的产品闭环。家庭 NAS 已承载实际同步，厘序与 MoneyWiz 进入并跑试用。P6 分别记录部署、设备验收和正式切换进度。

依据：[产品设计](product-design.md)、[首版需求](requirements.md)、[技术设计](technical-design.md)，以及本轮进度盘点和产品讨论。产品名“厘序”，codename `fine-ledger`。

## 1. 状态口径与本轮调整

- P0、P1、P2 按用户在本轮确认的本机范围记为完成，不因旧记录中的 NAS 门槛或后续功能反复退回未验收。

- MoneyWiz 旧账迁移已完成，作为现有数据基线；不再把首次转换／试导入排成后续必做任务。最终停用旧应用的切换时点、切换后新记录的回退属于 P6。
- 用户本轮确认主要流程已经验证通过；旧交付记录保留其原始版本和证据边界，未记录的长期稳定性、容量及性能量测集中放到 P6，不倒推已通过阶段失效。

- P4 报表已按用户“先实现所有报表需求”的授权交付 0.14.0；日／周／月／季度／年用于所有适用报表：趋势按期求和，净值／账户余额取期末值；0.14.1 按反馈将分类和项目收敛为区间汇总，不显示分期趋势。项目优先、折算内部维护的产品方向保留。154 项回归及本机浏览器视觉审核通过，用户已确认 0.14.3 验收通过，见[修订记录](report-review-v0.14.1.md)。P5 因使用频率低而后移；已有[手工对账草案](p4-reconciliation-product-proposal.md)仅作历史参考，届时结合 AI 辅助对账重新评估，不把整套手工工作页当作已批准的必做方案。P4 不依赖 P5 完成。

旧 0.13 计划完整保留为[历史快照](implementation-plan-v0.13-history.md)。历史文档中的阶段编号、待验收表和数量属于当时状态；当前排期及状态以本文为准。需求／设计中尚未同步的详细条款，在对应阶段先完成产品核对后修订，不把本次排期重整当作全部模型已定稿。

### P3-A 产品方案与最短路径

目标：把现有“先用人民币栏暂记外币数字，银行确认后修改”的操作，改为能保留币种和原始金额的正式流程。

- [x] 金额旁币种入口默认账户币种；选择不同币种后，可保存原始金额及“账户入账金额待确认”。不要求用户先猜一个账户币种金额。
- [x] 普通同币种录入维持现有简洁路径；按后续反馈取消手填暂估金额，原币未入账可直接等银行确认。
- [x] 列表按信息状态显示“原币金额／未入账”“最终账户金额／原始消费”，金额不得错标币种。
- [x] 点击未入账图标时，若正式金额未知，进入金额确认面板；填写实际账户金额后一次完成保存及入账。只编辑内容继续保留未入账状态。
- [x] 原交易身份、消费时间、描述、项目及原币保留；不生成第二笔消费。独立银行入账时间不作为日常必填，保留将来按需补充的可能。
- [x] 拆分在原币录入与账户金额确认间有明确比例／金额表达；确认时精确分配尾差，预览并允许更正，不要求重复输入所有类目。
- [x] 取消未入账消费可沿用删除路径；不虚构退款，不为此优先引入完整撤销工作流。银行中间折算金额不列为本阶段默认字段。

- [x] 可分离的转账手续费作为独立费用关联本金；产品上确认独立录入与合并银行扣款的展示方式，不新增自动账单导入。

### 验收

合成流程：CNY 信用卡消费 10,000 JPY → 原币保存未入账 → 实际 490 CNY → 确认入账。前后只有一笔消费，原币不丢，未入账时不进正式余额／报表，确认后只计一次。另验同币种未入账、真正 USD 账户、拆分尾差、重新编辑及双端同时确认不同金额的冲突。

本轮已落地表单、列表和确认面板，schema 4 保存原币与实际账户金额的区别，兼容旧 schema 3。验收收尾：

- [x] 用户完成本轮复验并确认 P3 可视为完成；此结论依据用户验收，未新增逐事件抓取或独立设备量测。最终版本综合验证继续按 P6 执行。

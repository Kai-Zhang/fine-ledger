# 厘序分阶段实施计划

版本：0.1  
日期：2026-10-27  
依据：[首版需求 0.3](requirements.md)、[技术设计 0.1](technical-design.md)

本计划覆盖从可行性验证到接替 MoneyWiz 的首版交付。产品名“厘序”，codename `fine-ledger`。本轮仅交付文档，不编写或修改应用代码，也不评估工作区其他实现文件。以下阶段均尚未按本计划验收，不因文档完成或代码文件存在而视为已完成。

实施以可运行、可恢复的小范围交付推进。先解决 iPhone 离线使用和数据保存，再逐步增加账务复杂度；早期验证迁移映射，正式导入和切换放在模型与同步稳定之后。

## 阶段总览

| 阶段 | 交付重点 | 依赖 | 用户能验证什么 |
| --- | --- | --- | --- |
| P0 环境与可行性 | 真机离线原型、NAS 部署验证、迁移映射样本 | NAS 和设备信息 | 飞行模式能启动和保存，家中能访问可信 HTTPS |
| P1 本地记账纵向流程 | CNY 账户、收支、分类、草稿、导出 | P0 | 手机完成真实操作路径，但仅用测试账本 |
| P2 同步与恢复 | NAS 账本、幂等、冲突、备份恢复 | P1 | 两设备同步、断网重试、不丢未上传内容 |
| P3 完整交易模型 | 多账户、转账、拆分、退款、项目、待入账 | P2 | 覆盖现有核心记账方式及第一种信用卡流程 |
| P4 外币成本与还款分配 | 默认还款区间、成本来源、覆盖与尾差 | P3 | 第二种信用卡流程和 CNY 成本闭环 |
| P5 对账报表与迁移演练 | 账户对账、CNY 报表、全量备份试导入 | P4 | 旧账可核验，报表可下钻且口径一致 |
| P6 首版切换 | 真机综合验收、正式迁移、恢复演练、运行说明 | P5 | 可以接替旧应用日常使用 |
| P7 低优先级扩展 | 还款分配手动调整、进一步交互优化 | P6 或核心路径稳定 | 处理复杂例外更便利，不改变默认流程 |

正常路径按 P0 → P1 → P2 → P3 → P4 → P5 → P6 顺序推进。可以提前准备后续合成样例和迁移映射，但不得以界面已完成替代数据完整性验收。P7 不阻塞首版；信用卡分期和预算界面不属于上述首版阶段。

暂不承诺日历工期。P0 得到目标设备、NAS 环境与实际交互验证后，再按阶段估算；范围改变时同步更新需求、设计和验收，不只修改排期。

## P0 环境与可行性验证

### 工作内容

- 确认目标 iPhone/iOS、其他常用设备、NAS 品牌型号、CPU 架构、容器或服务运行方式、本地持久卷和备份目标。
- 确认稳定域名、家庭 DNS、HTTPS 证书及续期方式；验证蜂窝网络不可达 NAS 时仍可从缓存启动。
- 锁定 Node.js、前端工具、SQLite 驱动及其原生依赖的兼容版本，验证数据库整数不会变成浮点数。
- 用最小合成账本验证主屏幕安装、离线冷启动、IndexedDB 提交、强退恢复、草稿、升级和持久存储申请结果。
- 验证 NAS 一致性快照、重启后的持久卷和基本恢复。此时只使用测试数据。
- 对 MoneyWiz 副本制作映射设计样本：用户域、实体继承、转账配对、重复别名列、时间编码、金额精度；不全面分析交易内容，也不修改原备份。

### 交付与通过条件

交付环境清单、兼容版本记录、真机操作录像或步骤记录、迁移字段映射草案和已发现风险。离线启动和本地保存必须在目标 iPhone 上成功，NAS 本地卷重启后保留数据，快照能恢复。

如果持久化或离线入口失败，先修复架构与部署；不能以桌面浏览器测试通过代替。NAS 尚未具备环境时可在本机验证逻辑，但该阶段的 NAS 门槛保持未完成。

## P1 本地记账纵向流程

### 工作内容

- 建立计划中的模块边界，产品界面使用“厘序”，代码及包引用使用 `fine-ledger`。
- 实现精确金额、业务日期和稳定 ID；先支持 CNY 现金／银行／信用卡账户、分类与单分类收支。
- 实现快速录入、常用账户和描述、账单列表、编辑、逻辑删除、草稿恢复。
- 本地保存交易与 outbox 意图同事务提交，即使此阶段尚未完整上传也保留未来同步入口。
- 提供带 schema 版本的完整本地导出，包含尚未同步的正式记录；草稿单独标识。
- 实现待同步提示与错误反馈，不允许网络失败阻止本地记录。

### 交付与通过条件

提供可在 iPhone 上安装的测试版。验证新增、修改、删除后强退重开结果正确；数据库写失败时不显示成功并保留输入；CNY 金额累计精确。初步测量启动和保存性能，记录设备与数据规模。

这是操作体验原型，不用于替换 MoneyWiz，也不把缺少同步和恢复的版本作为唯一账本。

## P2 NAS 同步与恢复

### 工作内容

- 实现单用户认证、设备会话、同源 API、SQLite 关系表、版本记录、操作回执和变更批次。
- 完成本地基线／工作副本／outbox 分离、依赖命令排序、请求冻结、幂等上传和事务化增量拉取。
- 实现冲突保存及最小解决界面；拒绝的操作保留用户内容，不反复无意义重试。
- 实现多标签协调、前台重试、认证过期处理和“本机已保存／NAS 已同步”区分。
- 实现完整快照初始化、每日一致性备份、独立备份目标和恢复 server_epoch。
- 写出恢复说明并进行一次模拟恢复，验证旧客户端不会自动覆盖恢复后的账本。

### 交付与通过条件

两台设备完成新增、修改、冲突处理并最终一致。模拟“服务器已经提交但响应丢失”，重试后仍只有一笔交易；重复拉取不重复应用。断电／终止进程模拟后，成功确认过的测试事务能在正常持久化条件下恢复。

恢复旧快照后，客户端识别代次变化，保留本机待上传内容和较新的已确认副本用于比较。备份恢复的账户余额和关系校验通过。只有 P2 完成后才允许开展可回退的小规模真实试用，仍保留旧应用与独立备份。

## P3 完整交易模型与待入账

### 工作内容

- 完成账户分组、账户归档、信用额度和多币种原币余额。
- 实现同币种／跨币种转账原子保存，手续费单独关联；删除与编辑不能留下半笔转账。
- 实现多级分类、分类拆分、项目关联及历史标签映射预览。
- 实现部分退款、多次退款、退款到不同账户及原支出可退量约束。
- 实现 pending／posted／voided，保存原币与银行中间 USD 信息，补填正式入账金额。
- 完成银行最终 CNY 入账流程：原交易身份保留、正式金额替换暂估、分类项目按比例分配、CNY 还款不重复计支出。
- 对上述跨实体修改接入 P2 的版本检查与冲突处理，不能只在单机通过。

### 交付与通过条件

合成场景中，一笔拆分消费可以跨项目且汇总不重复；多次退款不能超额；待入账撤销不生成退款；确认入账后余额只增加一次相应流水。待入账金额为空时不被当作零额消费或已对账流水。

在两设备上同时确认不同正式金额、同时退款或修改转账，应出现可解释的冲突。手机录入普通交易保持简洁，高级字段不占据默认操作路径。

## P4 外币成本与默认还款分配

### 工作内容

- 实现 CostSource、CostAllocation、RepaymentBatch、RepaymentCoverage 和必要的 CostSourceLink。
- 实现相邻还款日期区间，旧未偿本金优先，按入账顺序覆盖；首次、同日多次、超额和补记交易按设计处理。
- 实现跨币种购汇还款一步录入、自动分配和默认结果明细。无需用户逐笔确认正常分配。
- 支持部分还款、多次汇率、最大余数尾差，以及已偿本金与未知 CNY 成本分离。
- 支持先换汇后还款的手动来源选择；不增加自动跨账户资金溯源功能。
- 实现历史暂估、参考汇率、未定价显示和退款引起的成本冲减／汇兑差额。
- 实现批次输入版本冻结、账户分配版本保护和来源容量约束。手动改分配界面留到 P7，异常记录能保留待处理。

### 交付与通过条件

技术设计中的全部合成还款样例通过，两台设备争用同一来源时最多接受一个冲突版本，不能超额分配。三次以上部分结算后金额仍严格守恒；未知成本不使已偿本金在下次再次被覆盖。

插入较早交易不会悄悄改写已经确认的 CNY 成本。实际转账可以保存成功而分配处于待处理，两种状态清楚显示。一般还款只需填写两端金额，默认完成区间分配。

## P5 对账报表与完整迁移演练

### 工作内容

- 实现对账批次、逐项核对、差额、调整交易及正式完成前同步检查。
- 实现账户活动版本检查，保护对账期间新增流水；修改已对账本金或日期时重新核验后续批次。
- 实现月／季度收支、分类、旅游项目、账户余额和净资产报表，明确日期、退款、暂估、未定价与余额估值口径。
- 重计算放入 Worker，缓存按数据 revision、估值版本和筛选条件失效；验证报表可追溯至原交易。
- 完成全量 MoneyWiz 副本试导入，保留预算原始历史和旧标签，隔离旧认证字段。
- 实现导入预览、来源映射、重复导入幂等、余额与关系核验、迁移异常清单。
- 实现完整导出及回导，验证项目、退款和成本关系不丢失；CSV 仅用于通用阅读，完整恢复采用版本化导出。

### 交付与通过条件

对账差额非零时不能直接完成，已对账历史变化可追溯。月报和项目报表的合计与明细一致，待入账和转账不双计，缺失汇率不显示虚假的完整总额。

迁移核验报告至少覆盖需求文档中的账户、交易类型、转账对、拆分、退款、对账标记、标签和预算基线。所有账户原币余额与可验证源结果一致，无法解释的差异必须解决或明确确认后才能进入正式切换。

历史实际成本不足以验证时，保持历史暂估，不将新自动分配规则套回旧账后宣称全部精确。用户无需重建所有历史还款才能开始使用，但报表必须说明不确定部分。

## P6 首版发布与切换

### 工作内容

- 用目标 iPhone 主屏幕 PWA 和常用桌面浏览器完成完整验收矩阵。
- 验证飞行模式、离线冷启动、锁屏切换、强退、网络中断、登录过期、存储不足和应用升级。
- 在迁移后的实际数据规模上测量启动、保存和报表响应；检查软键盘、触摸目标和单手流程。
- 验证 NAS 重启、磁盘不足错误、备份告警和从独立介质恢复。
- 形成安装、日常同步、换机、备份恢复、升级和异常处理说明。
- 开展建议 7～14 天的日常试用，并完成至少一次代表性完整对账；长期稳定性仍需后续实际使用验证。

### 正式迁移与回退

1. 确定切换时点，暂停旧应用新增记录，导出最终一致备份；不删除旧应用或旧备份。
2. 冻结新账本正式写入，归档试用数据及待同步操作，明确哪些试用记录需要合并，避免重复。
3. 先将最终备份导入隔离目标账本，完成核验；失败时继续使用旧应用，不能留半导入结果。
4. 切换 NAS 账本代次，设备在家重新初始化，核对账户余额和待处理数量，再允许新应用独立使用。
5. 保留原始备份、切换后第一份备份和完整导出。若回退，导出切换后新交易并明确补录或转换方案；不假设 MoneyWiz 可直接接收新系统完整数据。

### 发布通过条件

需求中的首版验收条件均有结果；没有未解释余额差异、半笔转账、重复操作或静默冲突覆盖。真实 iPhone 离线冷启动和本地保存通过，独立备份恢复成功，用户能完成一次端到端对账。

P95 保存目标 200 ms、离线冷启动目标 2 秒需报告设备、样本数量、数据规模和测量方式。未达标时说明原因并修正或调整目标，不能以单次最快结果替代验收。

## P7 低优先级扩展

- 提供还款分配手动调整界面：选择消费、调整覆盖量、预览影响、提交替代版本。
- 支持重开受影响分配批次、修正首次起点和补记交易归属，并验证来源总量及后续批次。
- 在实际使用证据基础上优化记账快捷入口、项目选择和报表交互。

此阶段不自动扩展为信用卡分期、银行直连或预算管理。分期需要单独梳理本金、费用、账单、提前还款和对账规则后再设计。

## 测试与证据要求

| 层级 | 核心证据 | 不能替代什么 |
| --- | --- | --- |
| 领域规则 | 精确金额、守恒、状态与关系测试 | 不能证明真机保存或交互体验 |
| 数据库与协议 | 事务故障、重复请求、冲突、快照及恢复测试 | 不能证明家庭 DNS 和证书可用 |
| 浏览器端到端 | 表单、导航、离线资源和主要流程 | WebKit 模拟不能替代 iPhone 主屏幕运行 |
| 真机与 NAS | 保存后强退、离线冷启动、回家同步、实际恢复 | 不能仅凭截图证明长期稳定性 |
| 迁移核验 | 原币余额、实体关系、完整导出对照 | 数量相同不代表金额和关系正确 |

使用合成数据做破坏性和并发测试；真实备份仅在副本上核验。每阶段记录版本、设备、操作步骤、结果和未解决问题。测试失败后针对原因修复，不以增加重复测试数量代替解决问题。

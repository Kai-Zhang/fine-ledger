# 2026-10-29 外出后白屏追查与 0.5.1 修复

## 结论与边界

已修复一个可独立复现的启动阻塞：旧 Service Worker 在导航时先等待网络，只有请求成功或报错后才读取缓存。如果请求一直挂起，完整缓存也无法让首页启动。0.5.1 改为直接返回当前发布的固定缓存页面，更新检查在页面启动后进行。

用户在 0.5.1 上完成了飞行模式、Wi‑Fi 关闭、USB 拔掉的两次冷启动，两次均正常，并确认离线重启后版本仍为 0.5.1。

本次原始白屏在插入 USB 后、打开检查器前已经恢复，尚未捕获失败时的请求与进程状态。因此不能把网络等待确定为本次事故的唯一根因，也尚未解释 USB 插入为何能触发恢复。当前已确认的是代码缺陷、修复后的对应测试，以及用户真机离线验证结果。

## 修复

1. 有固定发布缓存时，首页直接从缓存返回，不发出阻塞启动的网络请求；优先用该发布的固定 HTML，保持页面与脚本一致。
2. 缺缓存时网络读取有 3 秒上限；失败返回可读的恢复页面，提示连接原服务器和重试，不返回空的 `Response.error()`。资源缺失同样有上限。
3. 启动 HTML 自带可见内容；独立的小启动脚本先于业务模块执行，8 秒未完成显示重试说明。普通已打开账本不会被该提示替换或清空。
4. 新增有界的本地技术记录：Service Worker 最近 50 项、页面最近 40 项，记录版本、阶段、缓存命中、错误类型及前后台事件。没有描述、金额、交易或账户内容，不上传服务器；日志存储失败不阻止打开账本。
5. 更新版本的 MessageChannel 等待和主动版本探测有超时；未保存编辑仍推迟更新。

地址、端口、原证书及 IndexedDB 账本名称/格式不变。发布标识为 `0.5.1-23749b0177a13144`。原 CA 校验通过：首页、Worker、发布清单和 8 项资源共 11 项均返回 200，内容与发布文件一致。

## 验证

- 新回归场景先在旧实现失败：让 `fetch` 永远 pending，有完整缓存也无法完成导航。
- 修复后同一场景无需网络即可返回固定缓存；在线与立即断网场景也走相同缓存页面。
- 覆盖缺缓存超时恢复、启动脚本顺序、可见启动说明、日志限量及日志存储失败不阻塞。
- 类型检查、构建和 36 项自动测试通过；金额、迁移、保存原子性、编辑保护、页面栈等原测试继续通过。
- 用户先在旧版、USB 连接下测试一次离线冷启动正常。这只作为对照，不能据此认定旧版无故障。
- 用户临时接入同一 Wi‑Fi，使用原图标重开后确认 0.5.1；随后拔掉 USB、关闭 Wi‑Fi、保持飞行模式，两次冷启动均正常，离线版本仍为 0.5.1。

若再次出现，优先保持网络和页面原状，记录发生时间、是否看见“正在打开账本”或“启动尚未完成”，再读取持久技术记录。不要先清数据或重新安装。即使接 USB 后恢复，新增记录仍能帮助分辨 Worker 导航、模块加载和数据库阶段。

检查方法依据 [Apple 的 iOS 检查说明](https://developer.apple.com/documentation/safari-developer-tools/inspecting-ios) 与 [WebKit 网络检查器说明](https://webkit.org/web-inspector/network-tab/)。Safari 普通网页和主屏幕 Web App 的状态分别验证，不用前者推定后者缓存健康。

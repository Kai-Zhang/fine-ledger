## 转换约定与待核对项

- 来源先复制 SQLite/WAL/SHM，在副本上用只读连接读取；复制前后和转换后的源哈希一致，副本 quick_check 为 ok。稳定身份由源 store UUID 和对象 GID 生成，不用金额/描述猜测交易重复。
- 金额从源有符号账户金额转换成精确最小单位整数。浮点噪声只允许到百万分之一个最小单位，真实超精度值拒绝转换，不静默舍入。转账严格验证两端互指、账户关系和同币种金额守恒，再合并为一笔；UTC 微秒和两端独立时间保留。
- 19 个账户按源期初加全量有符号流水重算，与厘序 balance 计算逐个一致。这是流水一致性校验，尚未由用户对照 MoneyWiz 界面的当前余额。源库 ZBALLANCE 为另一个缓存值，不用它生成平账交易。完整逐账户比较在私有报告中。
- 39 组原消费的同币种关联退款合计超出厘序当前限制，共 51 笔退款；另有 1 笔跨币种关联。共 52 笔保持 refund 类型、实际金额及类目，暂不建立 originalId；原关系保留在备注和源档案。不增大原消费、不删退款、不改成收入，也不在超额组内任意选择先关联哪些退款。
- 1 笔退款没有源类目分配，按原消费类目比例分配，使用整数最大余数法守恒，并在该笔备注说明。其他已有分配原样转为最小单位。
- 155 条交易各关联一个标签，映射为项目并放到各拆分项，没有复制交易或重复金额。全部 6 个项目保留。
- 对账标记与历史银行入账状态分开；本次源交易状态值均为 2，作为历史已入账数据导入，不把未对账记录改为 pending。MoneyWiz 的对账是核对银行记录的独立操作，参见其[官方手册](https://assets.wiz.money/MoneyWiz_Guide.pdf)；本转换不声称由状态枚举恢复银行批次信息。
- 原始金融行、对账标记、预算历史、类目分配及原始 ID 映射放入 `legacy.book` 源档案。本机文件导入后再次完整导出仍保留；现有远端仅初始化账本的接口不会接收此源档案。没有复制应用口令、登录凭据或非账务 App 配置。
- 账户未找到已确认的归档字段，不按名字或分组猜归档。原名称、分组和顺序保留；位图图标和数字颜色映射到现有视觉系统，原标识留在档案中。

此版本尚未复原完整对账批次、银行入账观察和成本分配。试用优先核对原币账户余额、较近的交易、跨币种转账两端、拆分/退款、项目筛选，再尝试新增、编辑和完整导出。用户仍以原软件核对过的记录决定正式切换。

## 复现与验证

迁移命令及专项测试现由独立的 `moneywiz-migrate` 项目提供；请参照其 README 执行。

工具只针对本轮观察到的 Core Data 字段结构。出现未知交易实体、状态/标志、非零独立费用、多标签需要分配、断裂转账、真实超精度或分配不守恒时拒绝输出，不宣称支持所有 MoneyWiz 版本。

真实交付文件通过 `decodeBackup`、`validateBook`、ZIP 精确往返、19 个账户源流水控制总额，以及隔离 fake-indexeddb 中实际 `importLocalBackup` / `exportBook`；账本和原档案导出后相同、outbox 为空、无远端基线、自动同步为 false。这个隔离测试不读取或替换浏览器账本，也不代表手机性能实测。

新增合成测试覆盖符号/币种精度、独立转账时间、项目与缺失退款类目、超额/跨币种退款、64 位源整数归档、损坏关系/未知状态拒绝，以及已提交 WAL 被读入且源未改变。Python 的 4 个用例由 Node 测试入口运行，现有完整回归共 109 项通过，类型和脚本语法检查通过。参见[聚合结果](evidence/2026-11-01-moneywiz-trial/summary.json)及[回归日志](evidence/2026-11-01-moneywiz-trial/tests.log)。

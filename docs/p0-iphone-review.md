# 新版 P0 iPhone HTTPS review

准备日期：2026-10-27。目标：在原来已经信任测试根证书的 iPhone 上，评审新界面和真实软键盘；本记录不表示真机 review 已通过。

## 访问与安装

Mac 与 iPhone 连接同一家庭 Wi-Fi，Mac 保持开机联网。Safari 打开：

**<https://zhangkaidemac-mini.local:8445/>**

无法解析 Bonjour 名称时，可固定使用备用 <https://192.168.0.241:8445/>。主域名和 IP 是不同浏览器来源，账本与缓存独立；选定一个后保持使用。不要使用旧 8443/8444 图标来评审新版。

1. 等待页面打开，再选 Safari 分享 → 添加到主屏幕。若出现“作为网页 App 打开”，保持开启；可将图标命名为“厘序 Review”方便区分旧版。参见 [Apple 官方安装说明](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)。
2. 从新图标联网打开一次。当前版本无需旧 demo 连接口令，自动初始化独立合成账本，尚未连接 NAS。
3. 账户 → 交易记录 → 记一笔，评审金额键盘、中文组合输入、描述候选、二级类目、分钟时间、底部保存按钮和连续录入。

复用原测试 CA 签发的现有服务器证书及私钥，没有生成或安装新 CA，没有更改 iPhone 信任设置。现有服务器证书有效至 **2026-11-26 10:31:29（Asia/Shanghai）**。如手机提示证书不受信任，停在提示页检查原证书状态，不绕过警告。

## 本轮准备与自检

- 新服务独立监听家庭 LAN `192.168.0.241:8445`，旧 8443、8444 和桌面 4180 服务仍在原 PID 运行。
- 服务器仅提供 `public/` 中的新静态 PWA；不会读取旧账本、旧口令或代理旧 API。运行状态、日志保存在被 Git 排除的 `.local/iphone-review/`。
- 使用原 CA 严格验证域名与 IP 的 TLS 身份；11 个预缓存资源均返回 200，响应字节与当前源文件一致。manifest 为 standalone，启动路径和 scope 均为根目录；192/512 图标可访问。
- 验证 start 重复调用复用实例、stop 仅识别自身 PID 与实例 ID，停止后可重新启动；最终已保持运行。
- 脚本语法检查及 10 项业务规则测试通过。原始 HTTPS 资源指纹见 [验证结果](review/iphone-https-verification.json)。

本轮没有代替用户在 iPhone 上执行安装、键盘输入、强退恢复或离线验收。优先收集本次真实记账与键盘反馈，再修正界面；完整 P0/P1 门槛仍以实施计划为准。

## 服务管理

```sh
npm run iphone:start
npm run iphone:status
npm run iphone:stop
```

默认复用根目录 `.local/iphone/config.json`、`server.pem`、`server-key.pem`、`ca.pem`，不读取 CA 私钥。可用 `IPHONE_CERT_DIR` 指定另一份已配置证书目录，`IPHONE_REVIEW_PORT` 指定独立端口；禁止误用旧 8443/8444。服务启停期间须使用相同配置。更换端口会建立新来源，不迁移已有浏览器数据。

## review 观察点

- 金额输入是否打开合适的数字键盘，保存按钮是否被软键盘遮住。
- 中文拼音组合时是否能正常选字，描述候选是否容易点中。
- 候选带入类目后能否方便修改，二级展开是否适合单手操作。
- 时间控件能否调整至分钟；备注输入时能否顺畅滚动。
- 连续记账是否保持账户，关闭再打开能否恢复草稿。

本版数据保存在该 iPhone 来源内，不会自动汇总回 Mac。需要留存 review 时新增的记录，可在设置导出 JSON。

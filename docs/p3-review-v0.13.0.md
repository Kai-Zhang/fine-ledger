## 操作

- 收支表单金额旁可切换币种，默认账户币种。与账户不同的币种先保存未入账；只知道原币也能保存，可另外填写账户币种暂估金额。普通同币种路径保留。
- 列表与详情正确显示录入币种；未入账原币显示“CNY 待确认”或暂估。账户余额、净值和正式报表继续排除未入账。
- 点未入账图标／详情的“确认入账”，输入实际账户金额并确认。保存同一交易身份、原币、消费时刻；没有新增银行入账日期必填字段。已知原币的既有记录也可在编辑页补充原始消费金额。
- 拆分类目按原比例和最大余数分配最小货币单位，面板展示并允许逐项调整；合计不符或出现零／负类目不能入账。并发更新时保留当前内容，要求重新打开／解决冲突。
- 信用卡账户可填信用额度，账户内显示额度与按已入账余额计算的可用额度；额度不计净值，不预扣未入账。
- 转账展开“手续费与备注”后可填本金之外的手续费和费用类目。手续费是独立支出，保存与转账在同一本机事务中完成，双向详情可查看关联。本金汇率不含独立费用。编辑已有转账时保留手续费自身入账状态；清空费用会逻辑删除对应费用。单独删除转账保留手续费并提前说明，可独立处理。

## 数据与兼容

使用 P3 新字段时将账本 `schema` 提升到 4；旧 schema 3 继续可读、可导入，不自动补造原币，也不更改源迁移档案。完整交换包外层仍为 v3，内部账本 schema 独立版本化。

`amountCurrency` 声明录入金额和拆分的币种，缺省仍为账户币种。跨币未入账的 `amountMinor` 是真实原币金额，不是零元账户流水；此时账户金额未知。`originalAmount` 保留原始币种／金额，`estimatedMinor` 可存账户币种暂估。确认后金额与拆分转换为实际账户币种，原始金额保留。`creditLimitMinor` 是可选额度；费用通过 `transferId` 指向转账。

服务端与客户端共同拒绝跨币录入值直接标为已入账、失配原币、非法暂估／额度、失效费用引用及 schema 降级。费用引用进入命令依赖排序与版本前提。SQLite 使用既有完整实体 payload，无需丢弃／重建数据库。新字段随快照、增量、冲突比较和 ZIP 本机恢复保留。

产生 schema 4 数据后，需要 0.13.0 或更新版本；旧版解码器会拒绝该结构，不能用旧版覆盖回写。P3 更新前保存的 schema 3 备份仍可恢复，恢复不会包含备份时点以后的记录。没有将逐笔还款成本分配或正式对账混入本次交付。

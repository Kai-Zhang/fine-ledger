# P3 反馈修订（0.13.1）

发布：`0.13.1-eee518768fa7a3e3`。沿用原 8445 HTTPS 入口、证书及账本数据。本轮根据用户反馈简化录入，修正账户列表可见性，并对 iPhone 留存的按钮叠字现场取证。

## 产品行为

- 去掉手填暂估金额，列表及详情不再展示暂估，也不在实际入账面板中预填历史暂估。历史备份中的 `estimatedMinor` 继续兼容保留，但新表单不生成／修改该字段。没有新增自动估值。
- 普通同币种新建不再显示“原始消费金额（选填）”。已有原币记录的编辑仍可查看／更正原币，确认入账后保留来源事实。
- 保存按钮继续使用原提示：普通记录“保存”，新建外币记录“保存为未入账”，编辑“保存修改”；未改为统一文案。
- 人民币账户默认列表包括该账户的外币未入账记录。账户中锁定的金额币种仅在填写金额上下限时限制比较；全局显式币种筛选保持原行为，金额不会跨币种直接比较。

## 按钮现场与局部修复

原页面保留于实际 iPhone 主屏幕 App；手机镜像看到与用户截图相同的叠字。USB 解锁后经 Safari Web Inspector 连接，实际运行资源为 `0.13.0-17d4954f6b1ba9f5`。

只读检查确认：只有一个 `.entry-submit`，一个按钮和一份“保存为未入账”文字。按钮矩形 x=16、y=779、398×48；span 为 95.27×22、字号 16px、行高 22.4px，Range 只有一行。视口 430×873、缩放 1、键盘状态 false；吸底容器为 sticky，滚动父级 form 为 overflow:auto，外侧 workspace 为 overflow:hidden 且 will-change:transform。上述结果不支持“DOM 里存在两段按钮文案”或实际文字换行为原因。

用户确认解锁后叠字仍在。随后只给当前按钮临时设置 `transform: translateZ(0)`，没有刷新、改文字、改业务状态或表单内容，按钮矩形保持不变；用户随后确认“已恢复正常”。正式样式固化相同的局部合成处理，并用 `translate3d(0,1px,0)` 保留按压反馈。未全局更改导航的合成规则。

该试验支持这是当前按钮绘制／合成异常，并验证了本次现场的消除办法；不据一次试验宣称已确定 WebKit 内部缺陷或所有设备永不复现。当前手机旧页面的临时样式维持至页面退出／更新，未强制刷新保留中的录入现场。最终发布版本的连续切换与键盘组合仍可继续真机复验。

## 列表与点击验证

已确认并修正账户默认币种过滤外币未入账的代码路径。用户此前“点击后消失”的完整真机原因仍未单独复现，不能将其归因于误删除或误入账。

隔离浏览器实际走通：CNY 账户新建 2,000 JPY 未入账 → 账户“全部”直接可见，余额不变 → “未入账”中点正文进入详情且状态不变 → 返回后点图标弹出实际金额面板 → 输入 100 CNY 并确认 → 从未入账筛选移出，在“全部”仍是同一笔 100 CNY／原始 2,000 JPY，余额仅减少 100 CNY。未向手机或 8445 账本写入这些合成记录。

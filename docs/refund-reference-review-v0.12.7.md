## 复核结论

源库的 631 条退款关联全部指向有效的原支出，没有断链或重复关系。第一版的 52 笔未关联，来自厘序将所有历史关联限定为“同币种、累计不超过原消费”的普通退款规则：

| 来源情况 | 数量 |
| --- | ---: |
| 同币种累计超额 | 39 组原记录，51 笔退款 |
| 上述组仅有一笔退款 | 34 组 |
| 上述组有多笔退款 | 5 组 |
| 51 笔中单笔未超过原金额、仅整组累计超额 | 16 笔 |
| 原记录与返款币种不同 | 1 笔 |

金额差异直接存在于源行；这 52 笔所用账户金额与源 original amount 字段一致，未发现符号、元/分、转账两端重复或选错原始金额字段导致的转换差异。描述中的代付、借出等场景说明历史关联不总是商品退款；利息、补差、舍入或误关联的具体原因不能仅凭这些字段断定。不能据此把这些关系统称为原始数据错误。第一版因整组超限而断开关联过于保守。

逐笔日期、描述、金额和币种仅写入 Git 忽略的个人交付目录 `artifacts/moneywiz-trial-2026-11-01-v2/退款关联核对.md`，本记录不披露个人交易行。

## 保留方式

- 579 条符合现有规则的关系仍为普通 `originalId`。
- 52 条使用 `Entry.refundReference`，记录 MoneyWiz 来源、原记录 ID 及超额/跨币种背景；它保留源关系，不断言同币种可退本金，也不推导汇率。
- 退款和原记录双方详情可以互相跳转，明确标为“MoneyWiz 历史关联”；跨币种返款展示其实际账户币种。
- 保留普通退款上限及币种校验。历史关联不能通过普通新增/编辑请求伪造、添加或改写；完整账本导入/初始化可载入源历史。存在活跃历史关联的原记录不提供自动新增退款额度，避免给出错误的剩余金额。
- 双向显示、删除原记录时是否连同关联退款删除、墓碑保留及恢复均识别历史关系。恢复源记录不会改本金或人为平账。

v2 包包含全部 631 条源关联。与 v1 对照，全部 16,248 笔记录的 ID、金额、币种、类型、时间、拆分、账户等字段及其余账本内容一致，仅给这 52 笔增加历史关联与相应备注。19 个账户源流水核验仍通过，源 SQLite/WAL/SHM 哈希未变。导入包要求 0.12.7 或以上版本显示和保护这些关系。

## 远端账本的含义

当前通用服务每个实例/数据目录只托管一本账本。评审启动脚本仅在数据库为空时写入合成账本；其后使用相同的普通服务、数据库、认证、同步与备份逻辑，没有演示 ID 特判或演示专用保护。

文件恢复只在本机 IndexedDB 替换账本、保存旧副本、移除旧同步基线并关闭自动同步，不发送远端覆盖请求。已有账本的服务拒绝再次初始化，账本 ID 不同也不能合并同步。因此“远端演示账本不会被覆盖”不表示服务器支持多账本，也不是演示硬编码的效果。正式托管迁移账本需使用空的服务数据目录/新实例，或在明确的替换流程中处理现有演示库。本轮没有替换远端账本。

## 金额和日期口径

- 收入、支出、退款按发生时间分桶求和；净支出 = 支出 − 退款，结余 = 收入 − 净支出。普通转账／还款本金、期初和余额调整不计日常收支；独立手续费计支出。
- 余额和净值取每个期间最后一个有效时点，不累加每日余额。历史日为日终，今天截至当前；不向未来期间预测余额。净值继续按账户原币余额乘既定区间依据汇总，不强求等于收支结余。
- 周一至周日、自然月、自然季度和自然年，按账本时区；首尾分桶裁到实际选定日期，跨年周显示起止日。无交易且无缺口的分桶补零，净退款保留负值。
- 交易先按完整拆分转换一次，再以稳定拆分 ID 分配最小单位尾差，随后应用类目／项目过滤。分类、项目、趋势及下钻共享这一结果，避免筛选后重复舍入改变总额；可能修正旧报表逐项取整形成的分值差异，不修改原交易金额。
- CNY 卡原消费 2,000 JPY、实际入账 100 CNY，仅计 100 CNY；未入账不统计，确认后归原消费期间。真正外币账户仍按原有规则折算。
- 退款按退款发生期计入；项目默认所有关联时间以包含后续退款。历史多项目只取明确分配；关联退款有未明确项目的部分时，提示项目金额可能不完整，并可查相关退款。
- 缺少依据时显示已计入部分和受影响记录，不假设为零。图表按指标分别判断完整性，缺少支出依据不会隐藏已知收入；净值缺口不画成零值连线。缺少期初／期末金额时不展示虚假的变化值。

账本仍接受 schema 3／4，备份外层仍为 v3，不新增空交易或回填猜测的历史事实。旧常用报表字段缺失时使用默认值；新报表类型及可选 `projectIds / grain / metric / chart` 经过服务校验、同步、ZIP 和 IndexedDB 恢复测试。使用新报表条件的客户端／同步服务应更新至 0.14.0，旧客户端不具备这些报表类型；不能用旧版客户端编辑后宣称完整兼容。

完整本机 ZIP 继续保留 legacy 源档案；仅下载普通远端快照不等于恢复这份源档案。未新增行情汇率、固定汇率或“实际成本”模式选择；这些仍按需定范围，当前默认内部规则直接提供报表金额。

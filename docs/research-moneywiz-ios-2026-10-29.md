# MoneyWiz iOS 实机竞品调研

日期：2026-10-29（Asia/Shanghai）
对象：用户现用 iPhone 15 Pro Max，通过 macOS“iPhone 镜像”直接操作。
实机版本：**MoneyWiz Premium 3.8.12，build 1110**，由“设置 → 关于 & 帮助”核实。
对应厘序基线：[产品设计 0.8](product-design.md)、[线框 v2](wireframe-review-v2.md)。

本次调研回答“哪些交互和功能表达值得借鉴”，不做市场排名或新版功能盘点。手机主屏幕名称为 MoneyWiz 3；不将 MoneyWiz 2026 的宣传、截图或功能套到这份实测结论上。

## 1. 结论

厘序目前的账户优先、描述补全、拆分类目、默认已入账、原交易发起退款、账户全局净值范围和报表筛选方向均有实机参照，不需要推翻设计。最值得补强的是：**把分类结构、图形、筛选后的金额和原交易连成一条可核对的路径**。

建议初版采用双层分类饼图的点选反馈、父子类目逐层展开、拆分的“本类金额 / 整笔金额”和统一的报表条件；保留厘序的紧凑账户列表、明确新增/管理职责、直接交易编辑、归档和手工两端金额。常用报表动态配置、负净支出、历史折算和秒级顺序继续按已经讨论的厘序规则设计，不能由竞品屏幕反推计算口径。

## 2. 操作与证据边界

- 已连接并实际浏览手机应用；连接成功，无需用户额外配对操作。
- 只读浏览账户、交易、账户配置与报表。以**未保存的表单**测试描述候选、多类目选择、拆分分配及跨币种转账字段，随后取消。
- **保存的新交易 0 笔，删除交易 0 笔；未创建、删除、修改或重排账户，也未改账户开关。** 未执行退款、银行连接、对账完成、汇率刷新、导出或分享。
- 临时在报表生成器增加了“账户：全部”筛选来查看选择器；未保存报告。此类浏览条件可能被应用记住，不属于账目修改。
- 已退出所有测试表单及账户配置，回到账户首页；可见总净值、原账户余额和最近交易与开始查看时一致。这是 UI 核对，不是数据库级校验。
- 直接观察到当前交易布局设为“自定义”。因此本报告描述**这台手机当前配置下的体验**，不把字段次序、折叠或图标颜色都称作出厂默认。
- iPhone 镜像以 Mac 鼠标/键盘操作，系统文字键盘的表现与手机手持输入有差异；没有完成原生拼音组合、单手触达、触摸拖动及边缘手势的真机验收。
- 报告不抄录个人账户名称、余额、商户、备注或消费构成，不保存真实财务截图到仓库。示例金额均为另行构造的说明。

调研中一次类目页转场未结束导致暂选了额外类目，已返回取消，父表单仍显示原类目并随后取消编辑；未点击原交易最终保存。文字粘贴在镜像中出现剪贴板时序差异，已清空该未保存输入，后续改用直接按键验证；不将该现象归因为 MoneyWiz 的补全缺陷。

## 3. 账户与交易：哪些做得连贯

### 账户先行，余额始终有上下文

首页先回答“钱在哪些账户里”，进入账户后再浏览或记账。账户交易顶部保留账户名和余额，底部有明显新增按钮，记录行还可显示逐笔变动后的余额（MW02、MW05）。这支持连续记账和对账，不需要每笔重复在长名单里找账户。

顶部总净值与账户原币余额并存；组内列出账户，组头可显示合计。组的眼睛图标和账户编辑中的净值开关处于不同位置，**不能仅凭图标假定它们具有相同的财务含义**。本次没有切换这些开关，也未验证归档。

厘序保留一行总净值和紧凑分组即可，无需复制大抬头和大卡片。逐笔余额对补记/对账有价值，可以在账户列表的对账场景按需显示，作为后续优化，不挤占第一版普通交易行。

### 新增与整理是两种操作

首页加号确实提供“新建账户 / 新建分组”；铅笔进入管理时显示删除控件和拖动手柄（MW03）。**只验证了手柄和管理状态，没有移动账户，不能声称已体验或量测其跟手效果。**

厘序采用已经确定的职责划分：普通模式加号新增；管理模式整理已有项目、右上角完成。不要照抄纯图标的语义负担，也不把新增账户/新增交易放进同一个模糊菜单。账户行删除控件更不能照搬到有历史记录的账户上；厘序继续提供归档。

### 列表原地展开，低频动作进入选项

当前列表点交易正文会展开，显示类目、备注以及“复制 / 选项”；选项提供修改、删除、待定、预定和退款（MW05）。这减少了浏览某条记录时的页面跳转，但会明显加高列表行，多个展开项会降低密度。

厘序首版保留独立详情和清晰编辑入口。可以借鉴“先看简短列表、需要时展开更多”的原则，不必同时增加另一套完整行内编辑。复制交易确有连续录入价值，但属于候选后续优化，当前不自动扩 MVP。

### 净值范围与单笔入账默认有账户级表达

账户的基本页有“自动确认交易”，扩展页有“在净值计算中包括”、分组等（MW04）。因此我们之前讨论的“纳入总净值”与临时报表选择分离有直接 UI 参照。

但本次未切换自动确认开关或交易图标，不以界面开关推断所有账户默认值。厘序继续采用已确定规则：新建默认已入账、列表图标切换、编辑不改原状态；首版不额外增加每账户默认状态配置。

## 4. 快速记账：借鉴减少重复输入，不照搬配置复杂度

### 描述候选与类目联动

空描述会出现一条横向历史候选。用直接按键输入一个拉丁字符时，候选中出现了该字符在描述中间的结果；大小写不同仍可匹配，说明这条实测路径支持包含匹配。选择历史候选后，描述和类目一起带入，金额仍待填写，焦点回到金额（MW06）。

本次没有穷举候选排序、跨账户复用范围、近期去重规则或手动类目覆盖优先级；不能声称 MoneyWiz 的排序就是“prefix 优先”。中文原生输入法组合也没有通过镜像完成验收。

厘序继续采用已经确定的最近描述、substring 匹配与 prefix 优先规则。值得增加的实现细节是：候选点选后保留已填金额和手动类目/拆分；焦点只去仍未完成的必填项，不机械地总跳回金额。

### 普通记账与拆分记账有不同复杂度

分类选择器含搜索和可展开父类；打开“跨多个类别的分割交易”后可多选。返回表单后右上角从保存勾变为下一步箭头，下一页才分配每个类目金额，并提供总额和锁图标（MW07）。

这套两步设计优点是普通单类目无需看到金额分配；代价是用户要在不同页面之间来回调整类目和分额，箭头/勾之间的变化也需要理解。此次查看了分配及输入反馈，但没有点击最终保存，也没有用有代表性的金额覆盖所有锁定/重分配规则。不能据此给出其精确尾差或负拆分校验的结论。

官方 MoneyWiz 3 移动版手册第 2.9 节也描述了先选类别、下一步分额、最后保存的流程，并说明锁图标用于保护指定金额。这里只用于核对导航含义，不替代当前版本实测。[官方移动版手册，第 64 页](https://assets.wiz.money/MoneyWiz3_Mobile_Guide.pdf#page=64)

厘序保留专门拆分页，但允许在同页增删类目和调整分额；总额、已分配、差额始终可见，不能完成时就地说明原因。当前无需为了仿照锁图标引入新的自动重分配机制。

### 金额键盘与更多字段

金额使用带四则运算的专用键盘，并有“下一步”；表单有“全部显示”展开更多字段。文字输入有应用内历史候选，但镜像中没有出现与手持 iPhone 相同的完整系统文字键盘（MW06、MW16）。

借鉴的是输入与候选靠近、低频字段折叠。四则运算可作为以后优化，不能让用户为了保存必须走计算器或下一步。MVP 仍以金额输入、候选和保存同时可达为先；不把简单/专业/完全自定义四套布局照搬为首版设置。

### 跨币种转账表达真实资金路径

选择不同币种账户后，表单出现转出金额、汇率、获得金额、发送和接收日期，描述自动表明两端账户（MW08）。本次看到参考数值和刷新入口，**没有刷新或验证报价是否实时、来源为何，也没有提交资金记录**。

厘序可借鉴两端对称呈现、账户决定币种、派生描述和必要时独立日期。MVP 仍手填两边实际金额，明确汇率方向；外部报价、刷新和 API 配置继续后置。不从该界面推断 MoneyWiz 的历史成本计算方式。

## 5. 报表：功能价值主要在可核对性

### 先配置再生成，生成后图表与明细共享场景

报告目录按主题分区；净值和结余走势是不同模板。实测净值模板生成前仅显示期限，结余走势模板另有账户选择；分类模板包含类目、图表类型、期限及按需添加的筛选器（MW09–MW12）。

这能控制每个模板的配置复杂度，但也让用户理解多个近似入口，并在返回配置和重新生成之间往返。厘序优先给净值走势与支出分类两个直接入口，把账户、时间、类目放在结果页易找的位置，低频项目筛选展开；不引入完整报告模板商城。

“图表 / 交易”的核心价值是**同一范围可以从概览回到数据依据**。不必照抄双页签：厘序可以沿用图表加金额列表及明细下钻，只要范围、所选类目和返回位置保持一致。

### 双层饼图已经实际验证

内圈为父类，外圈为对应子类；点外圈显示子类金额与占比，点内圈显示父类数值并高亮对应范围，其他部分降低突出度（MW13）。

图例同时罗列多个层级，类目较多时相当密集，部分名字重复，小扇区难点。厘序应：

- 保留父子角度对应、点选高亮和金额/占比反馈。
- 选中时显示完整类目路径，区分同名父子；采用稳定色彩与文字，不能仅靠颜色辨认。
- 下方金额列表可代替点极小扇区；默认不为零值显示扇区，不让长图例与大量零项占满首屏。
- 明确占比分母，默认按当前筛选范围的构成计算；如提供父类内占比，必须另行标注，不能在层级展开时悄悄换分母。

注意：实测这份报告中的二级类目百分比仍以整份报表合计为基准，而非自动切为父类占比。这是当前样本的可核对观察，不代表全部配置的规则。

### 父类 → 子类 → 交易，拆分同时显示部分和整体

“交易”页首先展示父类汇总，展开后有“父类 > 子类”路径，再展开到原始交易。未设子类的父项可直接展开交易；有子类时多一层。拆分消费在特定子类下显示**命中部分金额 / 整笔消费总金额**（MW14）。本次未继续逐项验证报表中交易行的编辑选项，不把账户列表的所有操作自动视为报表列表也已验证。

例如合成示意，一笔 120 元消费中有 30 元饮料，饮料明细显示 30 / 120。前者用于本类合计，后者说明它属于一笔更大的消费，点开仍能查看完整记录。这个细节最值得直接保留，它同时解决“为何这里金额不同”和“是否重复扣账户”的疑惑。

当前厘序设计已包含此语义；实现时应把它作为验收样例，而不是仅检查饼图能画出来。筛选多个拆分项、父子同时命中以及返回详情后的范围保持都要验证。

### 净值时点读数比面积装饰更重要

净值图显示期间、面积走势及高低参考线；点图后出现完整日期/时刻和金额提示，不必精确点中细线（MW10）。同一结果还能切到交易页。此次没有证明点击某个时点后，交易页会自动只保留该时点或该区间。

厘序保留易点选的时点读数和时点账户明细，提示框不挡住主要操作；缩短巨大空白，把日期与主币口径放清楚。阶梯、面积或折线样式可以之后调整，先保证已入账余额、区间折算、负债和来源缺口能核对。竞品的市场汇率或持久化模型没有通过屏幕得到验证。

### 保存报告有入口，动态重开语义尚未验证

报表加号菜单为“本地保存 / 导出 / 打印”；报表主页另有“保存”页。用户当前保存页为空（MW09、MW15）。本次没有保存、命名、删除或再次打开报告，因此**不能判断保存的是静态结果还是动态条件，也不能判断相对月份如何滚动**。

厘序已经明确保存常用报表的类型、范围、相对/固定时间与粒度，这个规则继续保留，不需要因为竞品未验证就改成静态截图。导出和打印入口的存在也不意味着必须加入当前 P1。

## 8. 面向实现的验收样例

1. 合成账本一笔 120 元消费拆为饮料 30、日用品 90；账户只扣 120，饮料报表只计 30，明细显示 30 / 120，详情看到完整两项。
2. 同时选父类和部分子类，不双计金额；切换范围后饼图、金额列表和明细统一变化，返回保留选择。
3. 用包含匹配找到描述并点选：已填金额不丢，类目按既定覆盖规则带入，手动拆分不被覆盖；原生输入法组合不被抢占。
4. 只看已入账正式合计，pending 在列表保留可见标记；点击图标切换和内容编辑保持既定语义。
5. 一个类目出现跨月净退款：按厘序的正值构成与净退款列表表达，完整净额仍可核对，不把退款按绝对值画成支出。
6. 管理模式新增入口不重复；账户拖动的取消恢复与顺序落位在测试账本验证，不对真实账户做破坏性研究。
7. 跨币种手填两端金额，无网络也可保存本机；实际汇率方向和区间来源可解释，不要求联网参考报价。

以上是厘序后续实现的目标，不是本次已经对 MoneyWiz 或厘序完成的自动化测试。

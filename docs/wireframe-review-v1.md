# 厘序交互线框 v1

日期：2026-10-28
依据：产品设计 0.6。
状态：四类线框已完成，等待用户 review；不是新的 PWA 发布，也不代表交互验收通过。

本轮线框在对话中直接点击查看，源片段存于 `docs/wireframes/interaction-v1.html` 供版本留存。所有名称、金额和交易都是合成示例；操作只改变当前线框内存，不读写现有账本、IndexedDB、同步服务或真实备份。现有 PWA、HTTPS 地址、端口和访问参数均未修改。

## 1. 页面与连通路径

| 核心页面 | 本轮可以 review 的内容 | 连通的次级状态 |
| --- | --- | --- |
| 账户首页 | 紧凑分组、原币余额、按币种组内合计、整行进入账户、行尾快速新增 | 账户交易、管理、上移/下移、移组、新增/编辑、归档/取消归档 |
| 记账 | 保持账户上下文；支出/收入/转账；金额、描述、类目、时间与状态；保存并继续 | 描述候选、二级类目、年月日时分秒、折叠项目/备注、离开确认、必填提示 |
| 交易详情 | 金额、账户、类目、时间、已入账状态、备注及关联退款 | 编辑、关联影响提示、退款、独立删除、确认入账 |
| 报表 | 报表入口与常用配置、净值走势、支出分类 | 日期、粒度、账户多选、父子类目多选、点选时点、展开子类目、下钻明细、保存常用 |

页面索引可以直达四类场景；产品内也可以沿“账户 → 账户交易 → 记一笔／详情”以及“报表 → 图表／分类 → 明细 → 交易详情”逐步浏览。返回按钮和左边缘向右滑使用同一导航层级，返回后保留当前报表条件。未保存改动离开时可继续填写或放弃。

## 2. 四条建议 review 路线

### 账户 → 连续记账

1. 点击“微信钱包”，再点击“记一笔”；也可直接点首页该账户行尾的加号。
2. 填金额，点描述。空输入出现 8 条最近不同描述；输入“咖啡”可比较“咖啡”“咖啡豆”“周末咖啡”的前缀/包含排序。
3. 点候选后带入类目；手工选择类目后不再被候选覆盖。类别按一级展开二级项。
4. 打开时间可选秒；普通页面只显示分钟。项目、备注默认折叠。
5. “保存”返回，“保存并继续”清空本笔输入并保留账户。描述和类目仍必填。

### 详情 → 编辑／退款／删除

1. 页面索引中的“交易详情”定位到一笔 299 CNY 的服饰消费，已有 50 CNY 关联退款。
2. 编辑更新原记录；金额变动时显示关联退款影响。
3. 从原消费发起退款，可选择其他活跃的同币种到账账户；超出当前可退额时显示错误。
4. 删除有退款的原消费可选仅删本笔或一并删除。保留退款时，退款详情仍可查看“原消费已删除”的关系。
5. 从交易页进入待入账列表，可在同一笔酒店记录上更正金额、确认银行入账日期，不新增第二笔消费。

### 账户整理 → 归档旧账

1. 首页“管理”显示排序和账户菜单；本版使用上移/下移完成排序，拖动手柄仅作位置示意。
2. 账户可更名、改组、设置是否计入净值；已用账户币种不开放直接修改。
3. 归档后从日常首页隐藏；已归档页可查看余额和旧交易，旧记录仍能编辑，取消归档前不提供新增入口。
4. 报表的账户选择保留归档账户，日常隐藏不会自动改变历史统计范围。

### 报表 → 筛选／下钻

1. 打开净值走势，默认近 12 个月；可改时间和日/周/月粒度，选择参与统计的账户。
2. 点选/拖动折线或使用下方时点控件查看数值，再进入该时点的账户明细和交易。返回保留筛选。
3. 外币按转账区间折算，尾段先用最近转入；折算来源入口解释 A、B 与暂定尾段。净值按原币已入账余额乘区间汇率。
4. 打开支出分类，默认本月。父类展开子类，选择器支持父项全选和部分选中，不重复累计父子金额。
5. 选空账户/类目显示未选择，而不是退回全部。只查看项目但没有已入账记录时显示空结果。
6. 保存为常用报表时区分相对期间和固定日期；保存后可从报表入口再次打开。

## 3. 本轮的表示边界

- 键盘是布局占位，可用来点选数字、查看候选与保存区位置；不代表真实 iPhone 输入法、组合输入、安全区或 VisualViewport 已通过验证。实际键盘需要后续真机 review。
- 左边缘手势模拟页面返回，不能代替 Safari 原生返回和主屏幕 PWA 的系统手势验收。
- 金额、账户余额和分类汇总可响应本次合成操作；净值历史曲线使用固定的合成余额样本。它用于评审筛选、粒度、时点和下钻，不能用来证明真实财务重算、成本分配或迁移正确。
- 正式统计示例只纳入已入账记录。待入账酒店不进入余额和报表；确认后才更新原记录。
- 低保真采用单色与线条，图标仅用于位置和识别讨论。密度及详情编辑入口可在设计选项中比较，不改变已确认财务口径。
- 本轮不展开首次建账、同步认证、备份恢复、分类设置 CRUD、分期专用计划、复杂已对账更正、跨币种退款及全部费用分摊流程。
- 未加入回收站或交易草稿列表；没有把分期、自动行情或主币切换重新带入 MVP。

## 4. 检查记录

检查使用独立临时 Chromium 页面读取线框预览，没有连接现有 PWA。已检查：描述 8 条候选、前缀/包含顺序、带入类目、秒选择、连续录入、编辑影响、独立删除、确认入账、归档旧账、手填转账两端、报表时间/粒度、空选择、父子类目部分选中、明细返回和常用配置。

已检查常规与窄屏预览、浅色与深色外观，无脚本运行错误；截图用于人工复核按钮、表单和图表可见性。这些检查只说明本份线框路径可操作，用户 review 结论仍待收集。

## 5. 本轮希望收集的反馈

| 位置 | 希望判断的具体问题 |
| --- | --- |
| 账户 | 默认紧凑程度是否合适；整行进入与加号新增是否容易区分 |
| 记账 | 输入和保存的顺序是否顺手；候选条与保存区的位置是否合理 |
| 详情 | 编辑入口放底部还是右上角更方便；退款与删除的关联提示是否足够清楚 |
| 报表 | 时间、账户与类目筛选是否易找；下钻层级、返回位置和暂定折算是否可理解 |

本轮不因线框完成而继续业务前端实现。下一步依用户反馈修改线框或确认后续实现范围。

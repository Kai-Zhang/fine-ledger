## 1. 五项反馈的对应修改

| 反馈 | 本版可检查的交互 |
| --- | --- |
| 一笔消费多个类目 | 类目行“拆分”进入明细分配；详情显示各项；报表按命中的拆分金额汇总 |
| 入账切换 | 新建默认已入账，编辑页不填状态；点列表左侧图标切换，正文仍打开详情 |
| 添加分组 | 首页“＋ → 新建分组”；“管理 → 管理分组”也可新建、更名、上移/下移 |
| 首页总净值 | 顶部一行主币总净值，点击进入默认净值范围的走势报表 |
| 净值范围设置的用途 | 改名“纳入总净值”，账户编辑中可展开解释；区别于报表临时选择 |

## 2. 建议检查的路径

### 一笔超市消费分到两个类目

1. 页面索引点“交易详情”，直接看到一笔 126 CNY 的超市消费：生鲜食品 86、日用品 40。
2. 点“编辑记录 → 拆分”可改每项金额、增删行、选择不同类目，或展开各项项目与备注。
3. 拆分页顶部显示总额、已分配及差额。合计不等于 126、金额无效或类目缺失时不能完成；修改交易总额也不会偷偷缩放拆分。
4. “记账”也可新增一笔拆分消费，描述及每项类目仍必填。整笔账户余额只扣一次。
5. “报表 → 支出分类 → 类目”只选生鲜食品，初始合计为 86。下钻显示命中部分，打开原交易仍见完整 126 与全部拆分；同时命中多项不会重复生成原交易。

### 点列表图标标记未入账

1. “账户 → 微信钱包”，点击“咖啡”左侧图标，标为未入账；文字区域继续进入详情。
2. 该行保留在列表并显示虚线图标及“未入账”。账户余额增加 28，首页总净值及正式支出统计同时排除这笔消费。
3. 编辑这笔消费的金额后，状态仍保持未入账；编辑页没有状态字段。
4. 再点图标入账，按修正后金额更新余额与报表；“待入账”按钮仍可单独筛选待确认项。
5. 转账从任一端切换状态，两端余额一起变化；不存在只入账一端的状态。

已对账或成本关联记录的正式保护仍按产品设计处理；此版没有完整构造对账批次与成本分配引擎。

### 新建分组与账户

1. 首页“＋ → 新建分组”，输入例如“家庭开支”。
2. 返回首页能看到空组与“添加账户”；从组内添加时默认选中该组。
3. “管理 → 管理分组”中可更名和上移/下移；名称与排序同步体现在账户首页。
4. 已归档账户继续从管理入口查看和取消归档，旧交易仍能直接编辑。

### 首页总净值与范围

1. 初始首页总净值为 74,956.50 CNY，使用已入账余额；组头仍按各原币分别合计。
2. 点总净值进入净值走势，使用“纳入总净值”的默认账户集合。
3. “管理 → 账户菜单 → 编辑账户”可看到“纳入总净值”及折叠解释。默认个人资产与负债均勾选。
4. 临时在报表中选择一个全局排除的账户，不会反向更改首页总净值；改变全局开关会改变首页及默认净值范围。
5. 归档钱包后首页不再显示钱包行，顶部总净值不因此减少；归档管理与资产范围相互独立。

“纳入总净值”主要用于同一本账中记录代管资金、公司款等非个人资产；日常少用的个人账户应归档。它不改变账户余额、分类支出统计或交易历史。显式保存固定账户集合的常用报表保留其集合，正式规则见产品设计第 7.4 节。

## 3. 检查结果与表示边界

使用独立临时浏览器检查了：新组与组内开户、全局净值范围与临时账户选择、拆分创建/编辑及差额拦截、分类筛选与原交易下钻、默认入账与图标切换、编辑保留未入账、转账两端切换、归档保留总净值及旧记录编辑。常规、320px 窄屏与深色外观已检查，无脚本运行错误。

这些结果只说明本份线框可操作。用户交互验收、真实 iPhone 键盘与边缘手势仍待 review。键盘是示意占位；历史净值是合成样本，没有验证正式财务引擎、完整折算缺口处理、成本分配或历史迁移。首次建账、同步认证、类目设置 CRUD、分组删除、跨币种退款及复杂对账更正不在本版展开。完整领域实现和数据一致性按实施计划逐阶段验收。

本轮不因线框检查通过而继续业务前端，也没有发布新的 PWA。

## 4. 2026-10-29 review 结论

用户表示整体方向改善，暂无更多建议，三项细节可留到代码实现：

1. 支出分类使用两层饼图，内圈一级类目、外圈对应二级类目，替代本线框的条形图。负净支出表示规则见产品设计第 11.3 节。
2. 操作柄需实现账户行跟随手指拖动、占位与落位；本线框只以菜单排序演示结果，不作为拖动交互验收。
3. 普通模式“＋”负责新增；“管理”进入整理模式，右上角只显示“完成”，移除重复添加账户入口。

对应[产品设计 0.8](product-design.md)和[实施准备度](implementation-plan.md)已更新。现有信息足够启动初版，没有阻塞性产品问题；无需为这三项再改线框。真实键盘、手势、离线、完整财务模型及迁移仍须按阶段验证。本次只评估与记录，不自动开始业务前端。
